# Малина в церкви + Telegram-бот

Инструкция · church-translator

Перевод работает на Raspberry Pi `shevchuk`, которая постоянно стоит в церкви. Mac на службу не нужен: запуск, остановка и все уведомления идут через Telegram-бота **@ctranslatebot**.

```
X32 (копия Main L/R) → Scarlett 2i2 → USB → малина → выходы Scarlett → FM-передатчики
                                              ↕ интернет (кабель LAN; Wi-Fi — запасной)
                             AssemblyAI · Claude · Cartesia · Telegram
```

Вся тяжёлая работа (распознавание, перевод, голос) идёт в облаке, поэтому качество и задержка на малине такие же, как на Mac.

## Разовая настройка (дома)

Уже сделано: код и зависимости лежат в `~/church-translator` на малине, `config.yaml` с клоном голоса пастора и `.env` с тремя API-ключами на месте. Включён linger, чтобы сервис стартовал без входа в систему. Правило WirePlumber не даёт PipeWire занимать Scarlett. Осталось:

1. Поставить системную библиотеку звука (нужен пароль sudo):

   ```bash
   ssh -t shevchuk@shevchuk.local 'sudo apt install -y libportaudio2'
   ```

2. Дописать в `~/church-translator/.env` на малине токен бота и свой Telegram ID:

   ```
   TELEGRAM_BOT_TOKEN=123456:ABC...          # от @BotFather
   TELEGRAM_ALLOWED_USER_IDS=111111111       # несколько — через запятую
   ```

   ID можно не искать: напишите боту что угодно, и он ответит «Ваш Telegram ID: …».

3. С Mac, из папки проекта: `deploy/deploy.sh`. Скрипт зальёт код, включит сервис и запустит бота. Бот пришлёт «🟢 Малина включилась…».

## В церкви

1. Подключить малину **кабелем LAN** к роутеру. Адрес она получит по DHCP сама, настраивать ничего не нужно.
2. Scarlett — по USB в малину, X32 → входы Scarlett, выходы L/R → передатчики 1/2 (как было с Mac). **Кнопка Direct Monitor (🎧) на Scarlett — отжата.** Если она нажата, английский оригинал идёт в передатчики поверх перевода. Дома её включают, чтобы слушать оригинал и перевод вместе; если забыть выключить, бот предупредит в сообщении при включении, в «Статусе» и при ▶️.
   Уровень входа — ручкой gain: ободок у ручки должен быть зелёным, иногда жёлтым, но не красным. Перегруженный (обрезанный) вход ухудшает распознавание.
3. Включить малину. Меньше чем через минуту бот напишет:
   - `🟢 Малина shevchuk включилась` — есть интернет, бот на связи;
   - `🎛 Звуковая карта «Scarlett» на месте` — Scarlett видна;
   - `🌐 кабель, IP …` — через какую сеть она вышла.
4. Первый раз на новом месте — **🧪 Тест каналов**: на приёмниках вместо перевода звучат два разных тона (на каждую услышанную фразу). Если в передатчике 1 один тон, а в передатчике 2 другой, каналы подключены правильно. Затем **⏹ Стоп**.
5. Перед службой — **▶️ Старт**, после службы — **⏹ Стоп**.

**Если нет кабеля — Wi-Fi.** На малине заранее настроен запасной вход через хотспот iPhone («iPhone Shevchuk »). Включить хотспот, подключить к нему Mac и выполнить `ssh shevchuk@shevchuk.local`, затем:

```bash
sudo nmcli --ask dev wifi connect "ИМЯ_СЕТИ_ЦЕРКВИ"
sudo nmcli con modify "ИМЯ_СЕТИ_ЦЕРКВИ" 802-11-wireless.powersave 2   # без энергосбережения: меньше рывков задержки
```

Имя сети регистрозависимо, сверять посимвольно.

## Кнопки

| Кнопка | Что делает |
|---|---|
| ▶️ Старт | Запускает перевод (режим из `config.yaml`, обычно боевой) |
| ⏹ Стоп | Останавливает. **После службы — всегда**: распознавание оплачивается за время открытого соединения |
| 📊 Статус | Идёт ли перевод, отставание, уровень сигнала с микшера, сеть, температура, место на карте |
| 🔄 Перезапуск | ⏹ и сразу ▶️ — если на слух что-то не так |
| 🧪 Тест каналов | Тоны вместо перевода, без API и без затрат |

Команды в меню бота: `/devices` показывает, какие звуковые устройства видит малина, `/log` — последние строки журнала.

Бот слушается только тех, чьи ID перечислены в `TELEGRAM_ALLOWED_USER_IDS`. Команда, которая дошла с опозданием больше 2 минут (например, нажата без интернета), не выполняется: бот попросит нажать ещё раз.

## Что бот пишет сам и что делает

| Сообщение | Значит | Что делает бот / что делать вам |
|---|---|---|
| ⚠️ Оборвалась связь с распознаванием | Интернет моргнул или сервер закрыл соединение | Сам перезапускает перевод. Если сразу не вышло, пробует каждые 30 с до 10 минут и пишет, когда получилось |
| 🔌 Звуковая карта перестала отвечать | Выдернут USB или пропало питание Scarlett | Сам перезапускает, как только Scarlett снова видна. Проверьте кабель |
| 🐢 Перевод отстаёт на N с | Интернет не успевает | Если отставание не уходит минуту, перезапускает. Проверьте, не качает ли кто-то в этой сети |
| 🔇 С микшера нет сигнала N мин | На вход Scarlett ничего не приходит | Проверить кабель X32 → Scarlett и шину на пульте |
| ❗ Ошибка перевода | Одна фраза не перевелась или не озвучилась | Перевод идёт дальше. Если приходит пачками и упоминаются кредиты — включить overages в Cartesia |
| ⛔ Перевод остановлен / так и не поднялся | 5 перезапусков за 15 минут или 10 минут неудачных попыток | Нужен человек на месте: интернет, Scarlett, потом ▶️ |
| ⏹ Автостоп: дольше 3 ч | Забыли нажать ⏹ | Остановлен, чтобы не платить за пустое соединение |
| ⚠️ Прошлый запуск оборвался посреди перевода | Малина перезагрузилась (питание) во время службы | Перевод сам **не** запускается — нажмите ▶️ |

Все пороги лежат в секции `bot:` файла `config.yaml` на малине. Бот перечитывает конфиг при каждом ▶️, поэтому перезапускать сервис после правки не нужно.

## Записи и место на карте

Каждая служба пишется целиком: английский вход и оба перевода, примерно 2 ГБ за 2 часа. Файлы лежат в `~/church-translator/logs/recordings/<дата>/`. Папки старше 21 дня (`logging.keep_days`) бот удаляет сам. Забрать запись на Mac:

```bash
rsync -av shevchuk@shevchuk.local:church-translator/logs/recordings/2026-09-14/ ~/Downloads/service-2026-09-14/
```

## Обновить код

С Mac в той же сети, что и малина: `deploy/deploy.sh`, или `deploy/deploy.sh shevchuk@<IP>`. Скрипт трогает только код: `.env`, `config.yaml` и `logs/` на малине остаются как есть. Бот перезапустится и пришлёт «🟢 …». Не запускайте деплой во время службы: он остановит перевод.

## Если что-то не так

| Видите | Что делать |
|---|---|
| Бот молчит после включения малины | Нет интернета или питания. Проверить кабель LAN и лампочки. С Mac в той же сети: `ssh shevchuk@shevchuk.local 'systemctl --user status church-translator-bot'` |
| `🔌 Звуковая карта «Scarlett» не найдена` | USB-кабель, питание Scarlett. `/devices` должен показать строку со «Scarlett 2i2 USB» |
| ▶️ → «Device unavailable» / «занята» | PipeWire снова держит Scarlett: на Mac заново `deploy/deploy.sh` — он поставит правило и перезапустит WirePlumber |
| В журнале `409 Conflict` | Этот же бот запущен где-то ещё (например, на Mac). Telegram отдаёт команды только одной копии |
| `⚡ не хватает питания` в статусе | Малине 4 нужен штатный блок 5V/3A: от слабого блока отваливается USB-звук |
| Журнал целиком | `ssh shevchuk@shevchuk.local 'journalctl --user-unit church-translator-bot -n 200'` |
| Перезапустить бота | `ssh shevchuk@shevchuk.local 'systemctl --user restart church-translator-bot'` |
